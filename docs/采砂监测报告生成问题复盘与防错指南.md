## 二、根因分析

### 1. 基本情况检索不到（知识库问题）

**根因**：知识库（LlamaIndex）中，固始县实施方案有"每个采区一个独立摘要切片"，而罗山县实施方案没有做 per-site 摘要，导致按采区名搜索时罗山站点匹配不到内容。

**修复**：重建罗山知识库（对罗山实施方案每个采区生成独立摘要 chunk），并增加"桩号推导可采区长度"逻辑（原文无长度时由桩号区间计算）。

### 2. 无人机影像灰色

两类根因：

- **单波段影像**：青龙闵塆、淮河村、吴乡村的专属影像文件本身只有 1 个波段（灰度数据）。灰度图没有颜色信息，无论如何拉伸对比度都只能是灰色。
- **影像与边界对不上**：史灌河童庙的专属影像与批复边界在南北方向相差 4 千多米（影像坐标系带号与边界不一致），裁剪取交集失败，回退到了全县灰度大图，于是也是灰色。

**修复**：
1. 检测单波段影像 → 自动改用 2026 年 1-2 月亚米高分彩色影像（按县分目录的 `.img` 文件，按采区中心点定位）。
2. 专属影像裁剪失败时 → 先回退高分彩色影像，最后才回退全县灰度大图。

### 3. 同一采区拆成两份报告

**根因**：青龙闵塆采区测点分两个 dat 文件（-1、-2），入库时站点名带后缀，批处理把它们当成了两个独立砂场。

**修复**：站点名归一化——输入"主名-数字"时，若去掉后缀的主名存在测点，则合并到主名生成一份报告（合法的"竹竿河-1"等带数字后缀站点不受影响）。

### 4. 多片测区只显示一片

**根因**：批复边界图（2026年采区.shp）里"李寨村采区"只有北片一个边界（约 390 米），但无人机实测了 **3 片测区**（南/中/北三簇共 9088 个点，范围约 3.8 公里）。裁剪窗口只按边界范围取，另外两片全被裁掉。

**修复**：裁剪窗口计算时把 RTK 测点包围盒并入——窗口 = 批复边界 ∪ 实测测点范围，保证影像图/高程图覆盖全部实测区域。

### 5. 高程点示意图不显示（坐标带号错误，本次最隐蔽）

**根因**：灌河道超、淮堰-周集、叶岗、沈营（以及淮河闾河口港区）的 RTK 测点**导入数据库时用错了坐标带号**：
- 数据文件实际是 **114°E 中央经线**的投影坐标；
- 导入时按 **117°E 中央经线**转换 → 所有测点经度整体偏移 **+3.0°**（约 280 公里），测点全部落在批复边界和影像范围之外。
- 结果：高程图视野聚焦错误位置，边界外的测点几乎看不到，标注只剩 1~3 个；影像裁剪窗口被错误测点撑到"假交集"，正射图基本是空白底图。

**修复**：
1. 数据库层面：6 个站点共 6.9 万测点用 `x_4547/y_4547` 原始坐标重新投影修正（+3° 偏移全部消除）。
2. 代码层面：`import_rtk_dat.py` 增加**经度合理性校验**——转换后经度超出信阳地区范围（112.5~117.5°E）立即报错终止，防止再次导入错带号数据。

### 6. 大营-范营影像图缺失

**根因**：批复边界图（2026年采区.shp）中**没有**"史灌河大营-范营可采区"边界（只有相邻的"史灌河童庙可采区"）。边界匹配失败 → 裁剪失败 → 影像图缺失。

**修复**：边界匹配失败时自动用相邻的"童庙采区"边界兜底（两个采区相邻、基本同范围），配合测点包围盒扩展，裁剪成功出图。

## 三、防错核心原则

1. **坐标系是最大的坑**：测点（dat）、批复边界（shp）、影像（tif）三套数据可能来自不同坐标系。**每次导入/生成前必须验证三者范围是否重合**。
2. **数据要能自我校验**：任何坐标转换后都应做合理性检查（经纬度范围、与已知边界重叠度），而不是直接信任转换结果。
3. **影像来源要有优先级链**：专属彩色影像 → 高分彩色影像 → 全县灰度大图，逐级回退并记录来源到 notes，出问题可追溯。
4. **裁剪范围要"以实测为准"**：批复边界可能不全（只有部分测区），裁剪窗口必须并入实测测点范围。

## 四、生成前检查清单（下次批量生成必做）

### 第 1 步：测点数据检查（最重要，坐标系错误源头）

```sql
-- 1) 经度合理性：信阳地区应在 112.5~117.5°E
SELECT site_name, round(ST_XMin(ST_Collect(geom))::numeric,4) AS lon_min,
       round(ST_XMax(ST_Collect(geom))::numeric,4) AS lon_max, count(*)
FROM rtk_points GROUP BY site_name ORDER BY site_name;
```
- 任何站点经度 < 112.5 或 > 117.5 → **该站点坐标带号错误**，先修数据再生成。
- 导入新 dat 时：`import_rtk_dat.py` 已内置校验，报"超出信阳地区合理范围"即为带号选错，改用正确 `--epsg` 重导。

```sql
-- 2) 测点与批复边界是否重合（抽查即可）
-- 用站点名查 shp 边界（2026年采区.shp）与测点范围对比，应基本重叠
```

### 第 2 步：影像检查

- 站点专属影像是否单波段（灰度）：`_is_single_band` 已自动检测并回退高分彩色影像，无需人工干预；
- 但建议抽查生成日志：出现"正射影像来源：高分彩色影像"说明原影像灰度/裁剪失败，属预期回退；
- 高分彩色影像目录：`/mnt/arcgisorgdata/2026001_河南省2026年1_2月亚米遥感影像/信阳市/{县代码}{县名}/*.img`（按县分目录）。

### 第 3 步：站点名检查

- 同许可证多采区（如 `青龙闵塆采区-1/-2`）是否已在批处理列表中合并为一个条目（用主名）；
- 站点名与 `rtk_points.site_name`、shp `Name` 是否一致（不一致时用 `kb_area_query` 参数指定采区名）。

### 第 4 步：生成后检查

- 批处理日志中每份报告状态：`正射✓ 高程✓`，出现 `✗` 或 `FAIL` 的站点单独排查；
- 抽查 2~3 份报告：
  - 正射影像图是否为彩色（灰度=单波段/回退失败）；
  - 高程点示意图红色标注是否成片（几十个标注以上）；
  - 采砂场基本情况是否检索出内容（"资料未见"过多=知识库问题，检查 KB 是否已重建该县 per-site 摘要）。

## 七、标题/散文/图注规范化（2026-08 批次）

> 目标：对齐《2025采砂报告》（docs/2025采砂报告.docx）采砂场监测章节效果。

### 1. 本次改动

| 维度 | 旧 | 新 |
|---|---|---|
| 站点标题 | "{{site_name}}采砂监测分析报告（许可证号：…）" | 采砂场=许可证号（豫潢砂许〔2025〕第1号）；工程=规范工程名（潢川县白露河上游防洪能力提升工程） |
| 基本情况 | 固定句式 + 大量"资料未见"，工程类字段被强制清空 | 按参考文风从知识库原文生成散文段（左岸/右岸、规划采区编号等原文细节）；失败回退旧句式 |
| 无人机航测句 | 一律"对{{permit_no}}采砂区域…（桩号…）" | 采砂场：对许可证号采砂区域+桩号；工程：对工程名+批复工程范围 |
| 图注 | 原始 site_name | 统一规范站点名 display_name |
| 合并报告 | 分页拼接 | 县区章节 + 三级编号（1.X.Y 式），每县末尾补"采砂场监测评估意见"占位 |

### 2. 关键实现

- `backend/tools/caisha_report_tool.py`：`_is_project`（工程类判定）、`_display_name`（去"南-南1/-01"分段后缀）、`_normalize_permit`（括号统一〔〕）、`_retrieve_basic_chunks`（检索重构）、`_extract_basic_prose`（散文生成 + `_build_basic_fallback` 兜底）。
- 散文 prompt 强约束：只依据原文、保留单位、缺失写"资料未见"、严禁把其他采区数据写入、工程类禁止套用采砂条款；LLM 输出异常（过短/JSON/代码块）自动回退兜底句式。

- 单元测试：`backend/tests/test_caisha_report.py`（16 个用例，覆盖类型判定/名称规范化/许可证规范化/散文兜底/模板渲染）。

### 3. 生成前检查清单（本批次新增）

1. **标题检查**：采砂场报告首行应为许可证号（括号为〔〕、无空格）；工程类报告首行应为规范工程名（无"南-南1/-01"等分段后缀）。
2. **散文检查**：基本情况为一段散文，数值与实施方案原文一致；"资料未见"只应出现在原文确实缺失的字段；工程类正文不得出现采砂条款（采砂期限/机具/许可总量）。
3. **图注检查**：现场监测图片/正射影像图/高程点示意图的图注均使用 display_name，图号按节顺延（现场图 1..N → 正射图 N+1 → 高程图 N+2）。
4. **合并报告检查**：章节编号为 1.X县区采砂区监测与评估 → 1.X.Y站点标题 → 1.X.Y.1 基本情况 → 1.X.Y.2 监测实施情况，每县末尾有评估意见占位标题。
5. **数据依赖**：工程类散文依赖实施方案知识库包含该工程资料（当前潢川县 KB 缺少白露河工程详情，需补充《防洪能力提升工程砂石处置方案》类文档入库后重新生成）。
6. **本轮验证范围**：仅验证砂场类站点（郝楼砂场等）；工程/疏浚类站点（如潢川县白露河上游防洪能力提升工程）本轮不测试，其标题/散文/图注代码已就绪，待补充工程资料后另行验证。
