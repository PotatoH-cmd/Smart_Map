# 豫水智能一张图（Map Assistant v1）项目总结

> 面向水利勘测与河道采砂监管的 **AI 智能地图助手**：将大语言模型、空间分析、遥感变化检测与知识库问答融为一体，提供"对话即操作"的地图交互体验。
>
> 本文档由代码库与项目资料整理而成，作为项目整体介绍、交接与汇报材料。

---

## 一、项目概述

**豫水智能一张图** 是一款面向水利行业的多模态 AI 地理空间分析平台，深度融合大语言模型（LLM）、计算机视觉（CV）与地理信息系统（GIS）三大技术体系，为农村水利管理、河道监管和采砂治理提供智能化决策支撑。

系统以**自然语言对话为核心入口**，通过 AI 智能体自动编排空间查询、遥感识别、知识检索、报告生成等能力，把专业 GIS 分析的门槛从"需要专业软件操作"降低到"像和人对话一样简单"。

| 项目属性 | 内容 |
|---|---|
| 项目名称 | 豫水智能一张图（Map Assistant v1） |
| 项目定位 | AI 驱动的地理空间智能分析平台 |
| 业务领域 | 水利勘测、河道采砂监管、河道侵占识别 |
| 交互形态 | 自然语言对话 + 2D/3D 地图 + 工具面板 |
| 代码规模 | Python 约 1.4 万行 + React 约 1 万行（合计约 5 万行含样式/脚本） |
| 部署方式 | FastAPI（后端 8006 端口）+ React（前端 3003/3004 端口），PM2 托管 |

## 二、建设背景与业务痛点

| 痛点 | 说明 |
|---|---|
| GIS 软件门槛高 | 专业空间分析需 ArcGIS/QGIS 操作经验，基层人员难以掌握 |
| 河道巡查效率低 | 靠人工比对影像与红线，发现侵占行为周期长 |
| 遥感分析周期长 | 影像分割、变化检测、图斑筛选流程繁琐 |
| 报表工作重复枯燥 | 周报/月报需人工拼接数据、截图、图表 |
| 政策法规查询难 | 规范条文分散在大量文档中，检索费时 |

**目标**：用 AI 技术降低专业工具使用门槛，让一线水利工作者便捷地使用遥感检测、空间查询等高级功能。

## 四、核心功能模块

### 4.1 AI 智能对话与任务编排（核心）

- 用户通过 **SSE 流式对话**（`/chat/stream`）输入自然语言。
- **意图识别**：IntentAgent 输出结构化意图结果（意图类型、置信度、实体、执行计划），并支持 **快速关键词路由**（约 60+ 条规则绕过 LLM 直击意图，降低延迟与成本）。
- **Agent 分派**：AgentHarness 按意图分派到 MapAgent / DataAgent / KnowledgeAgent / ReportAgent / GeneralAgent（兜底）。
- **执行编排**：TaskExecutor 以 LangGraph 三节点状态图（意图节点 → 工具节点/响应节点）执行任务，实时推送执行状态（run_id + 事件流，前端 `RunStatusBar` / `ProgressTimeline` 展示）。
- **工具调用链**：按需调用 15+ 工具，前端根据 `map_commands` / `cesium_commands` / `charts` 等指令实时渲染地图与图表。
- 支持**多轮上下文管理**（context_manager）与 **Rules Gateway 规则网关**（合规拦截/参数校验）。

### 4.2 双地图引擎与图层管理

- **2D 视图（Leaflet）**：日常巡查与数据浏览；支持 ArcGIS 切片、高分影像、OSM 等底图；图层控制、点位抽稀、视口自适应渲染。
- **3D 视图（CesiumJS）**：地形分析与工程展示；3D Tiles、无人机航拍模型叠加；WebSocket（`/ws/cesium`）实现场景指令实时同步。
- **切片管理（TileManager）**：MVT 矢量瓦片、无人机 MBTiles、3D Tiles 的注册、构建（含异步任务与进度）、发布与删除；卫星影像瓦片服务（`/api/satellite_tile`）。
- 两套引擎共享图层数据与空间分析结果，指令跨视图自动路由。

### 4.3 多模态遥感检测与河道侵占识别

三阶段检测流水线：

1. **SAM 分割**：SAM3 对高分影像全图分割，识别水体、建筑、植被、道路等地物；支持双头掩码融合（Dual-Head Mask Fusion）提升小目标精度；前端 SAMPanel 提供交互式标注。
2. **变化检测**：基于双时相影像对比（OmniOVCD 框架），支持本地 Ollama 视觉模型与 DashScope 千问 VL 双后端弹性切换。
3. **图斑后处理**：重叠合并（buffer-union-shrink）、聚集密度分析、大面积单体规则（≥5000㎡ 自动标记可疑）、VLM 二次确认，自动归类"确认/疑似/排除"，人工审核量降低约 70%。

### 4.4 智能报告生成

- 自动整合 **RTK 测点、无人机影像、监测数据**，一键输出 Word 报告（python-docx 模板 + 占位符填充，`create_template.py` / `update_template.py` 维护模板）。
- **地图截图自动嵌入**：前端截图代理捕获当前地图视图，嵌入报告正文。
- **知识库增强**：自动检索水利标准条款作为报告依据。
- **在线预览**：Mammoth 将 Word 实时转 HTML 预览，支持打印与下载（`/api/preview/report`、`/api/download/report`）。

### 4.5 知识库智能检索

- 双后端切换：**RagFlow**（默认，远程服务）与 **LlamaIndex**（本地，支持 Kuzu 图数据库知识图谱）。
- 知识内容覆盖采砂规范、监测规范、实时实施方案等 150+ 篇水利标准与法规（`backend/scripts/` 提供导入脚本）。
- 可视化知识库管理界面（KnowledgeBaseManager）+ 知识图谱查询（`/api/knowledge/graph`）。
- 兜底机制：数据库查询无结果时自动回退知识库检索。

### 4.6 数据查询与可视化

- **自然语言转 SQL**：直连 PostgreSQL + PostGIS（postgresql_tool / mcp_postgres_tool），支持模式查询、数据查询、统计分析。
- **图表可视化**：对话式生成柱状图/饼图/折线图/散点图（ECharts），前端做数字格式化、文本换行、主题统一等后处理。

### 4.7 空间分析与 GIS 工具链

- **QGIS MCP 集成**：Docker 化 QGIS 空间分析引擎，支持缓冲区、裁剪、叠加、相交、面积计算、分区统计等 recipe 工作流（`qgis_workflows.py`）。
- **空间参考工具**：河道红线、采区边界查询，"红线附近/范围内"空间语义自动识别。
- **空间处理工具**：坐标转换（CGCS2000 带号处理）、XY 交换、GeoJSON 矢量生成与地图加载。
- **GIS 路由网关**（gis_tool_router）：统一分发各 GIS 处理能力。
- 辅助：天气查询、位置搜索、坐标标注、地理编码等。

## 五、智能体编排架构（Agent Harness）

```
用户输入 → IntentAgent（LLM 结构化意图识别 / 快速关键词路由）
         → AgentHarness（意图→Agent 分派 + 提示词组装 + 系统上下文注入）
         → TaskExecutor（LangGraph 三节点状态图执行）
              ├─ intent_node（意图解析）
              ├─ tool_node（调用工具，实时推送事件）
              └─ response_node（结果合成自然语言回复 + 前端指令）
```

| 领域 Agent | 覆盖意图 | 主要工具 |
|---|---|---|
| MapAgent | 地图展示/位置搜索/坐标标注/空间处理/空间参考 | map_tool、cesium_tool、spatial_processing_tool、spatial_reference_tool |
| DataAgent | 数据查询/可视化 | postgresql_tool、data_visualizer_tool |
| KnowledgeAgent | 知识检索 | knowledge_base_tool（RAGFlow/LlamaIndex） |
| ReportAgent | 报告生成 | report_generator_tool、caisha_report_tool |
| GeneralAgent | 兜底（未知/天气/跨意图复合） | 开放全部工具 |

意图体系：12 个意图类型（MAP_DISPLAY、DATA_QUERY、KNOWLEDGE_SEARCH、DATA_VISUALIZATION、REPORT_GENERATION、SPATIAL_*、WEATHER、LOCATION、COORDINATE、CROSS_INTENT、UNKNOWN）+ 子意图与结构化执行计划（TaskStep）。

新增工具/Agent 遵循约定：工具继承 `qwen_agent.tools.base.BaseTool` → 在 tool_registry 注册 → 定义意图类型 → 在 AgentHarness 分派与快速路由中挂接；提示词统一在 `backend/prompts.py` 维护（单一来源原则 SSoT）。

## 六、关键创新亮点

1. **智能体空间感知**：自动识别"红线附近 / 可采区内 / 河道两侧"等空间语义，调用空间参考工具获取边界并作为隐含参数注入后续查询，实现"一句话完成空间分析"。
2. **多模型协同与弹性降级**：云端千问 API + 本地 Ollama 视觉模型双后端，大图本地推理保障隐私与带宽，云端故障自动切换。
3. **图斑智能后处理管道**：重叠合并 → 聚集密度分类 → 大面积规则 → VLM 二次确认，将数千碎片图斑归纳为三类，人工审核量降低约 70%。
4. **双地图引擎协同**：2D/3D 指令跨视图自动路由，宏观分析用 2D、地形展示用 3D。
5. **全链路可观测性**：对话日志、工具调用链、RunEngine 执行事件流、PM2 进程监控。
6. **对话即报告**：从对话到含地图截图、图表、法规依据的 Word 报告全自动生成。

## 九、部署与运维

- **后端**：conda 环境 `mapagent6`（Python 3.10+），端口 8006，`start.sh` 或 `python main.py` 启动，API 文档 `/docs`。
- **前端**：React（CRA），开发端口 3003，PM2 生产端口 3004（代理至后端 8006）。
- **PM2 双进程托管**：`ecosystem.config.js`（map-assistant-backend / map-assistant-frontend，1G 内存保护自动重启）。
- **灰度开关**：环境变量 `RUN_ENGINE=on` 启用新 RunEngine 执行路径，可回退旧 execute_stream 路径。
- **外部依赖**：PostgreSQL + PostGIS、GeoServer（可选 8088）、QGIS MCP Docker、RagFlow/LlamaIndex、DashScope API、天地图/Cesium ION Token。
- **数据目录**：vector_tiles（MVT）、drone_imagery（无人机 MBTiles）、3dtiles_data（3D Tiles）、llama_index_storage / kuzu_graph（知识库）、static（报告/截图/GeoJSON）、sessions.db（会话）。

## 十二、总结与展望

**项目核心价值**：用 AI 技术降低专业 GIS 工具的使用门槛，让科技真正服务于基层水利管理，为"智慧水利"和"数字乡村"建设贡献力量。

**已实现**：对话式地图操作、遥感侵占识别、智能报告、知识库问答、空间分析、数据可视化等完整能力闭环。

**未来方向**：
1. 深化多时相遥感变化检测，实现月度级河道侵占自动巡查；
2. 引入无人机实时视频流 AI 分析，支撑应急响应；
3. 打通政务系统数据接口，实现"发现问题 → 执法处置"业务闭环。
