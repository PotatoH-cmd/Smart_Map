# 周报模块系统性优化方案

## 现状分析

- **现有周报类型**：部门周报(dept)、小组周报(group)、个人周报(person)，均位于 `ruoyi-project/ruoyi-digital` 模块
- **现有生成流程**：`TbReportWeekDeptServiceImpl.genReportContentStream()` 硬编码查询DB -> 组装数据 -> 调用 `TscDealUtil` 生成提示词 -> 前端发送到 AI 模块 `/chat/stream`
- **AI模块**：`ruoyi-ai`，基于 Spring AI 1.1.7 + Spring Boot 3.4.3，已有 ChatClient 池化 + 流式输出
- **项目详情页**：`sub_project_detail/index.vue`，已有5个tab（概览/任务/团队/文档/动态）

## Task 1: 项目周报数据模型与后端CRUD

**目标**：在 `ruoyi-digital` 模块新增项目周报（project）类型

### 1.1 数据库表设计

新建 `tb_report_week_project` 表（参考 `tb_report_week_dept` 结构，增加 `sub_project_id` 字段）：

```sql
CREATE TABLE `tb_report_week_project` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT,
  `sub_project_id` bigint(20) NOT NULL COMMENT '生产项目ID',
  `report_name` varchar(200) DEFAULT NULL COMMENT '周报名称',
  `title` varchar(200) DEFAULT NULL COMMENT '周报标题',
  `markdown_content` longtext COMMENT 'Markdown内容',
  `file` text COMMENT 'Word文件JSON',
  `begin_date` date DEFAULT NULL COMMENT '开始日期',
  `end_date` date DEFAULT NULL COMMENT '结束日期',
  `status` char(1) DEFAULT '0' COMMENT '状态(0草稿 1已发布)',
  `create_by` varchar(50) DEFAULT NULL,
  `create_time` datetime DEFAULT NULL,
  `update_by` varchar(50) DEFAULT NULL,
  `update_time` datetime DEFAULT NULL,
  `del_flag` char(1) DEFAULT '0',
  PRIMARY KEY (`id`),
  KEY `idx_sub_project_id` (`sub_project_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='项目周报';
```

### 1.2 后端代码生成

在 `ruoyi-project/ruoyi-digital` 中新增：
- `TbReportWeekProject.java` (domain)
- `TbReportWeekProjectMapper.java` + XML
- `ITbReportWeekProjectService.java` / `TbReportWeekProjectServiceImpl.java`
- `TbReportWeekProjectController.java`
- `genReportContentStream()` 方法：参考部门周报，但按单个 `subProjectId` 过滤数据

### 1.3 API接口

在 `ruoyi-ui-digital/src/api/digital/` 新增 `reportWeekProject.js`

## Task 3: 定时任务自动生成项目周报

**目标**：通过 `ruoyi-job` 模块定时触发项目周报生成

### 3.1 定时任务配置

- 在 `ruoyi-job` 中新增 `ProjectReportJob`，每周五18:00执行（可配置）
- 任务逻辑：遍历所有活跃生产项目 -> 为每个项目调用 `ruoyi-digital` 的周报生成接口
- 生成的周报以"草稿"状态存入 `tb_report_week_project`，用户后续可在Tab页查看和编辑

### 3.2 跨模块调用

- `ruoyi-digital` 暴露 Feign API 供 `ruoyi-job` 调用
- 在 `ruoyi-api/ruoyi-api-digital` 中定义 `RemoteProjectReportService` 接口

## Task 4: 基于Spring AI Advisor编排的周报生成Pipeline

**目标**：将周报生成从硬编码改造为可编排的Advisor链

### 4.1 架构设计

在 `ruoyi-ai` 模块中构建周报专用生成管道：

```
ReportGenerationPipeline
  ├── DataCollectAdvisor     -- 数据采集（通过MCP/Feign调用digital模块获取任务数据）
  ├── PromptAssembleAdvisor  -- 提示词组装（加载模板 + 注入数据 + 日期替换）
  ├── KnowledgeEnhanceAdvisor-- RAG增强（从知识库检索相关上下文注入提示词）
  ├── AiGenerateStep         -- AI生成（流式输出Markdown）
  └── PostProcessAdvisor     -- 后处理（格式校验、排版修正）
```

### 4.2 核心实现

新增 `com.ai.report` 包：

- `ReportPipeline.java`：编排类，组合多个Advisor为ChatClient调用链
- `DataCollectAdvisor.java`：通过 RestTemplate/Feign 调用 `ruoyi-digital` 获取项目任务数据
- `PromptAssembleAdvisor.java`：加载 `tsc_digital.txt` 或项目专用模板，将数据注入占位符
- `KnowledgeEnhanceAdvisor.java`：连接向量存储，检索历史反馈优化提示词
- `ReportController.java`（新增）：提供 `/report/generate/stream` 端点，替代当前前端直调 `/chat/stream` 的方式

### 4.3 配置化

在 `AiProperties` 中增加周报相关配置项（模板路径、数据采集URL、是否启用RAG等）

## Task 5: 版本管理与结构化反馈库

**目标**：为周报建立版本追溯和用户反馈闭环

### 5.1 版本表设计

```sql
CREATE TABLE `tb_report_version` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT,
  `report_type` varchar(20) NOT NULL COMMENT '类型(dept/group/person/project)',
  `report_id` bigint(20) NOT NULL COMMENT '周报ID',
  `version_no` int(11) NOT NULL COMMENT '版本号',
  `markdown_content` longtext COMMENT 'Markdown内容',
  `file` text COMMENT 'Word文件JSON',
  `source` char(1) DEFAULT '0' COMMENT '来源(0编辑器保存 1Word上传)',
  `change_summary` text COMMENT '变更摘要（与上一版差异）',
  `create_by` varchar(50) DEFAULT NULL,
  `create_time` datetime DEFAULT NULL,
  PRIMARY KEY (`id`),
  KEY `idx_report` (`report_type`, `report_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='周报版本';
```

### 5.2 反馈表设计

```sql
CREATE TABLE `tb_report_feedback` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT,
  `version_id` bigint(20) NOT NULL COMMENT '版本ID',
  `report_type` varchar(20) NOT NULL,
  `report_id` bigint(20) NOT NULL,
  `original_text` text COMMENT '原文片段',
  `modified_text` text COMMENT '修改后文本',
  `feedback_type` varchar(50) COMMENT '反馈类型(幻觉/格式/内容缺失/措辞)',
  `comment` text COMMENT '用户备注',
  `synced_to_kb` char(1) DEFAULT '0' COMMENT '是否已同步到知识库',
  `create_by` varchar(50) DEFAULT NULL,
  `create_time` datetime DEFAULT NULL,
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='周报反馈';
```

### 5.3 版本对比功能

- 后端：基于文本diff算法（如java-diff-utils）计算两版差异
- 前端：在编辑器旁增加版本历史面板，支持版本切换和diff可视化对比

### 5.4 Word上传作为新版本

- 复用现有文件上传能力，上传Word后解析为Markdown（通过pandoc或Apache POI）存入新版本

## Task 6: RAG向量知识库

**目标**：利用Spring AI VectorStore将反馈沉淀为可检索的知识

### 6.1 向量存储依赖

在 `ruoyi-ai/pom.xml` 中增加：
- `spring-ai-starter-vector-store-pgvector`（基于PostgreSQL pgvector）或
- `spring-ai-starter-vector-store-redis`（如果已有Redis则更轻量）

### 6.2 知识库写入

- 当用户提交反馈（`tb_report_feedback`）时，异步将 `original_text -> modified_text` 对及其上下文向量化写入VectorStore
- 定期批量同步历史已标记的反馈记录

### 6.3 知识库读取（RAG增强生成）

- `KnowledgeEnhanceAdvisor` 在生成周报前，用当前任务数据摘要作为query检索Top-K相关反馈
- 将检索结果作为额外上下文注入提示词，避免重复犯错

### 6.4 知识库管理

- 提供简单的管理页面，支持查看知识库条目、删除过时条目、手动导入知识
