2

一次请求的完整流转

从用户输入到结构化输出
1

快速关键词路由

TaskExecutor 先问 harness.try_fast_classify()，命中高频命令即绕过 LLM，构造 confidence=0.95 的意图

2

LLM 意图分析（未命中时）

IntentAgent.analyze() 用结构化输出得到 IntentResult：意图 + 实体 + execution_plan

3

路由决策

_route_after_intent 依据置信度 / 是否确认 / 是否需要工具，决定去 END、response_node 还是 tool_node

4

并发执行工具

按 execution_plan 经 ToolRegistry 创建实例、QwenToolAdapter 统一包装，asyncio 并发调用

5

汇总响应

取 harness.build_response_prompt_for() 话术 + get_system_context() 时间，LLM 汇总为自然语言

✓

返回前端

response + map_commands + cesium_commands + charts + report_url

4

路由决策表

_route_after_intent
intent_result is None — 意图分析失败
→ END 直接结束
confidence < 0.3 — 置信度过低
→ END 兜底回复
requires_confirmation — 需要用户确认
→ response_node 生成确认文案
execution_plan 中没有工具
→ response_node 直接回答
有需要调用的工具 —— 正常路径
→ tool_node 并发执行
直接结束 进入响应节点 进入工具节点

稳健性兜底机制

TaskExecutor 内置容错
DB 空结果 → 知识库回退
数据库返回空/失败/可疑聚合值时，自动追加 knowledge_base_tool 检索，响应阶段再同步补偿
报告数据充分性检查
报告工具等前置工具完成后先校验数据；不足则跳过生成，避免产出空报告
富结果直通
工具已返回高质量 Markdown 摘要时直接透传，跳过 LLM 二次汇总，省时省 token
